# MapKit 与 MapKit JS 更新摘要

本次分享介绍了 MapKit 和 MapKit JS 的一系列重要更新，旨在帮助开发者更便捷地将 Apple 地图的强大功能集成到 App 和网站中。核心更新涵盖了地点查找、地理编码、路线规划和街景展示等方面。

---

### 1. 全新的地点引用方式：PlaceDescriptor

为了解决在没有唯一地点标识符（Place ID）的情况下查找地点数据的问题，Apple 推出了 `PlaceDescriptor`。

*   **核心功能**: 允许开发者使用结构化的地点描述（如名称、地址、坐标）来请求丰富的 MapKit 地点数据。
*   **适用场景**:
    *   从外部 API 或 CRM 系统获取地点信息（只有名称和地址）。
    *   当 App 需要与其他不使用 MapKit 的应用（如通过 App Intents）交换位置信息时。
*   **实现方式**:
    *   位于新的 `GeoToolbox` 框架中。
    *   通过组合 `commonName`（通用名称）、`representations`（地址、坐标等）和 `supportingRepresentations`（其他服务商标识符）来构建描述符。
    *   使用 `MKMapItemRequest` 传入 `PlaceDescriptor` 即可获取对应的 `MKMapItem`。

### 2. 地理编码 API 迁移至 MapKit

地理编码功能（正向与反向）已从 `CoreLocation` 框架迁移至 `MapKit`，并提供了更强大的地址表示能力。

*   **API 变更**:
    *   `CLGeocoder` 和 `CLPlacemark` 将被弃用。
    *   推荐使用新的 `MKGeocodingRequest`（正向）和 `MKReverseGeocodingRequest`（反向）。
*   **增强的地址表示**:
    *   返回的 `MKMapItem` 包含 `MKAddress` 和 `MKAddressRepresentations` 属性。
    *   `MKAddressRepresentations` 提供了多种格式化选项，如 `cityWithContext`，可根据上下文智能显示最合适的地址信息（例如“加利福尼亚州洛杉矶”或“法国巴黎”），简化了 UI 开发。

### 3. 路线规划 (Directions) 与平台扩展

Directions API 迎来了重要功能更新和平台扩展，为用户提供更丰富的出行选择。

*   **新增骑行路线**:
    *   MapKit (Swift) 和 MapKit JS 现在均支持获取**骑行路线**。
    *   骑行路线会智能规划适合自行车的路径，如小径，并避开不适合的道路。
*   **watchOS 支持**:
    *   超过 20 个 MapKit API 现已登陆 watchOS，开发者可以将地图与路线功能直接集成到 Apple Watch App 中。

### 4. “四处看看” (Look Around) 登陆 Web

MapKit JS 现已支持“四处看看”功能，允许开发者在网站中嵌入 Apple 地图的 360 度交互式街景。

*   **两种视图模式**:
    1.  **交互式视图**: 可在网页中嵌入一个用户能够自由导航的“四处看看”窗口。
    2.  **预览视图 (Preview)**: 显示一个静态快照，点击后可进入全屏交互式体验。
*   **开发者控制**:
    *   提供丰富的配置选项和事件监听器（如 `load`, `error`, `close`），便于开发者自定义行为和UI。

### 5. 统一的地图 URL

Apple 更新并统一了地图链接的 URL 格式，使其参数更一致、简洁且易于阅读。这有助于开发者创建可靠的通用链接，在不同平台（包括网页版 Apple 地图）上提供一致的跳转体验。

---

### 核心建议

开发者应采取以下行动以充分利用新功能：
*   **采用 `PlaceDescriptor`**: 在没有地点标识符时，使用此新方法来查找地点。
*   **迁移地理编码**: 将 App 中的地理编码实现从 `CoreLocation` 迁移到新的 `MapKit` API。
*   **集成新功能**: 在 App 和网站中添加骑行路线和“四处看看”功能，提升用户体验。
*   **更新地图链接**: 采用新的统一 URL 格式，确保链接的稳定性和跨平台兼容性。
